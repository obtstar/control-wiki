# 05 Agent 编排层（后端服务）

编排层由**平台后端代码仓库 `control-api`（Java Spring Boot）**承担，负责任务管理、流水线状态机、多任务并发调度与自我升级，是全系统的调度中枢。数据落地 MySQL（DDL/DML 在 `control-db`）。编排配置与注册表版本化于控制中心仓库 `orchestration/` 与 `registry/`。

## 技术选型

| 组件 | 选型 | 说明 |
|-----|------|------|
| 框架 | Java Spring Boot | Spring MVC + Spring Data JPA/MyBatis |
| 安全 | Spring Security | 单用户认证（本地 token / 内网 SSO 可选） |
| 调度 | Spring Scheduling / Quartz | 定时任务、Webhook 触发 |
| 异步 | Spring Async / 消息队列 | 任务派发、RAG 索引任务 |
| 存储 | MySQL | 任务、工作记录、文档索引元数据 |

## 流水线状态机（自动流转）

```
[需求分析] ──→ [系统设计] ──→ [编码实现] ──→ [测试验证] ──→ [待合并] ──→ [交付]
    ↑              ↑              ↑              ↑             ↓
    └──────────────┴──────────────┴──────────────┴── 任意阶段可人工介入（暂停/回退/修改）
```

- **无审批闸门**：各阶段完成后自动进入下一阶段，报告与产物实时推送 Web 端
- **人工介入点**（非闸门）：用户在任意阶段可暂停、批注修正、回退；Agent 接收反馈后继续
- **合并**：测试验证通过后进入"待合并"，**合并动作为用户在 GitLab 人工执行**（平台创建 MR 并完成本地预处理验证，不执行合并）；Webhook 回传合并事件后任务进入交付，记 `work_log`
- **自动质量关**：进入"待合并"前，用 `heavy` 模型对 MR Diff 做自评审查（正确性/安全/契约一致性），**自评报告 + 测试全绿**才允许进入待合并；自评不通过则打回编码阶段修正

| 阶段 | Agent 动作 | 输出物 |
|-----|-----------|--------|
| 需求分析 | 解析需求，检索 RAG，生成影响分析 | 影响分析报告 |
| 系统设计 | 生成接口定义、数据库变更、时序图 | 设计文档（提交控制中心仓库 MR） |
| 编码实现 | 创建 feature 分支 + Worktree，编码、单元测试 | Commit + MR |
| 测试验证 | 执行节点跑集成测试、回归测试、静态检查 | 测试报告 |
| 待合并/交付 | 推送 MR 与测试报告；用户在 GitLab 合并到 release/dev，Webhook 回传后清理 Worktree | 合并记录 |

## 任务管理（单人多任务）

| 能力 | 说明 |
|-----|------|
| 任务分解 | 将需求/缺陷拆分为可执行子任务 |
| 多任务并发 | 多个任务并行执行，按 Worktree 配额与执行槽位限流（14.6） |
| 上下文管理 | 跨阶段维护任务上下文（需求、影响分析、设计决策） |
| 仓库分配 | 根据任务类型分配到目标代码仓库 |
| 分支/Worktree 生命周期 | 创建、回收、归档（配合代码仓库 OpenAPI） |
| 任务级熔断 | 连续失败 N 次或单任务 token 超阈值 → 自动暂停 + Web 通知（防自动流水线失控烧预算；token 计数记 `work_log`） |

## 自我升级

- 基于执行日志统计成功率，生成策略优化建议
- Prompt 版本化存 Git，升级即提 MR，用户在 GitLab 合并后生效
- 热加载免重启（15.7），重大策略变更可先单任务灰度再全量
