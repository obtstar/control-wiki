# 18 权柄与有据模型

项目级知识库的分级权柄、一致性校验与"有据可依"约束。本模型约束所有流水线阶段与 Agent 行为，是流水线的宪法。

## 18.1 权柄等级（项目级 KB）

| 级别 | 文档 | 权柄 | 写权限 |
|-----|------|------|--------|
| L1 | 需求 | **最高**：一切下游产出不得违背 | **仅人** |
| L2 | 概要设计 | 服从 L1，约束 L3/L4 | **仅人**（AI 可给建议稿，落笔必须是人） |
| L3 | 详细设计 | 服从 L2，约束 L4 | **仅人**（同上） |
| L4 | 代码 | 服从 L3 | Agent 直接产出，流水线审批闸把关 |

- **AI 对 L1-L3 零写权限**：任何情况下 Agent 不得创建/修改/删除权柄文档——**即使人指令它改也不行**。人想借助 AI 时，AI 只能输出建议稿（会话/MR 描述中），由人亲自把内容落进 wiki；AI 收到此类指令时应暂停流水线并提示"请手动修改 wiki"
- **项目级 > 平台级**：项目 KB 的 L1 约束高于平台通用规则/prompt/流程；冲突时以项目 L1 为准
- 权柄标注：KB 文档 frontmatter 携带 `authority: L1|L2|L3|L4`，蒸馏/索引时保留，检索结果按级别排序

## 18.2 有据可依（Grounding）

**一切产出必须有根据，禁止凭空联想**：

- Agent 的每个设计决策、接口定义、代码实现，必须在产出物中**引用 KB 依据**（文档 ID + 段落），无引用视为无据
- 流水线阶段入口先做**依据检索**：本阶段任务在 KB（项目级优先，平台级兜底）中找不到依据时，**不得自行发挥**，转入暂停并说明缺失的依据是什么
- 蒸馏（piekbs distill）只提取与转述，不生成原文没有的事实；`key_claims` 必须可回溯到 `raw/` 原文
- 审批时人可抽查引用链：产出物 → 引用段落 → raw 原文，三级可点验

## 18.3 一致性校验与暂停

| 校验点 | 动作 | 冲突处理 |
|-------|------|---------|
| 设计阶段（L2/L3 产出） | 对照 L1 需求逐条核对 | 冲突 → 报告 + 暂停 |
| 编码阶段（L4 产出） | 对照 L3 详细设计 | 冲突 → 报告 + 暂停 |
| 权柄文档变更（人改 wiki） | 检查在跑任务是否受影响 | 受影响 → 暂停相关任务，恢复后按新文档重做对应阶段 |

**不一致报告（AI 的唯一动作）**：发现上级文档之间/产出与上级文档不一致时，**即使人指令 AI 修改需求或设计文档，AI 也不得修改**，只能产出报告并暂停任务。报告必须包含：

1. **不一致点**：哪两份文档/哪两个段落的哪条内容互相矛盾（附原文引用）
2. **原因分析**：矛盾的性质（遗漏/过时/语义冲突/需求变更未同步）
3. **修改建议**：应改哪份文档、改哪段、建议改成什么（建议稿，供人参考）
4. **影响范围**：受该不一致影响的在跑任务与已有产出

**流程**：AI 出报告 → 任务暂停 → 人读报告、亲自修改 wiki → 人恢复任务 → AI 按新 wiki 重做对应阶段。

**暂停是最高运行时权限**：

- 任何状态、任何角色（人/平台/熔断器）都可触发暂停，立即生效，不可被覆盖
- 暂停期间 Agent 停止一切写操作（代码、wiki、远端）
- 恢复只能由人执行；恢复时以**当前最新 wiki 为准**重新校验，必要时回退到权柄变更点之后的阶段重做

## 18.4 人的通道（仅两条）

1. **改 wiki**：改变方向/需求/设计的唯一合法途径——**人亲自编辑**权柄文档（L1-L3 均只有人能写），不走口头/批注私令，也不指令 AI 代笔
2. **暂停/恢复流水线**：唯一的过程干预手段

除这两条外，人不下达任何形式的临时指令；阶段审批驳回时的批注仅作为"重做指引"，不构成新需求——新需求必须落到 wiki。
