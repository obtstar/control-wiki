# 07 工作流

平台包含三类工作流：功能开发（瀑布流水线）、Bug 修复与自我升级。所有流程**自动流转，无审批闸门**；合并动作为用户在 GitLab 人工执行，平台只做本地预处理验证与 MR 创建。

## 7.1 功能开发流水线

见 [05-orchestration.md](05-orchestration.md) 的状态机定义。流程为：

```
[需求分析] ──→ [系统设计] ──→ [编码实现] ──→ [测试验证] ──→ [待合并] ──→ [交付]
    ↑                                                  用户在 GitLab 人工合并
    └──────────────────── 任意阶段可人工介入（暂停/回退）──────────────────┘
```

## 7.2 功能追加 & Bug 修复（双轨模式）

| 模式 | 触发 | 工作流 |
|-----|------|--------|
| **功能追加** | Web 端需求单 | 完整流水线（需求→设计→编码→测试→合并） |
| **Bug 修复** | 告警/工单/用户录入 | 定位→复现→修复→回归→合并，轻量流水线 |

### Bug 修复流水线

```
Bug 报告 → 相似 Bug 检索(历史库) → 根因分析(LLM) → 生成补丁 → 本地测试
   ↑                                                        ↓
   └──────── GitLab 人工合并 ← MR + Diff ← 回归测试报告 ─────┘
```

## 7.3 自我升级模块（元能力）

```
自我升级循环：
┌─────────────┐     ┌─────────────┐     ┌─────────────┐
│ 执行日志分析 │ →  │ 策略优化建议 │ →  │ 配置热更新   │
│ (成功率统计) │     │ (LLM 反思)   │     │ Prompt/Skill │
└─────────────┘     └─────────────┘     └─────────────┘
       ↑                                      ↓
       └────────── 效果验证(A/B 对比) ─────────┘
```

### 升级管控

- **Prompt 版本化**：存 Git，升级即提 MR，用户在 GitLab 合并
- **Skill 管理**：采用 **openskills** 工具统一管理（SKILL.md 格式），技能目录存控制中心仓库 `orchestration/skills/`，版本化 + MR 管控；第三方技能 **vendor 入库**，不直连外网 registry（出站白名单仅放行 LiteLLM 端点）。**pi 原生支持 Skills**（能力包按需加载、渐进披露），openskills 仅作管理层，无格式适配成本
- **Extension 扩展**：pi 的 TypeScript 扩展（permission-gate / protected-paths / sandbox 等官方示例可复用），版本化管控
- **工具权重优化**：根据历史成功率动态调整工具选择
- 生效顺序：MR → GitLab 合并 → （可选单任务灰度）→ 热加载（15.7）
